# Персональное портфолио в области ИИ

Текущее оформление — мастерская в стиле TF2: тёмный металл, светлая состаренная бумага, кирпично-красные акценты и локальный кириллический шрифт. Фон и прозрачный инженер хранятся отдельно. У инженера восстановлены руки и продолжено тело до обуви; на сайте он показан крупным планом с кадрированием около пояса по предоставленному скриншоту. [Ресурсы, замена и параметры CSS](docs/tf2-assets.md), [промпты imagegen](docs/tf2-image-prompts.json), [промпты исправления персонажа](docs/engineer-repair-prompts.json), [проверка исправленного инженера](docs/engineer-repair.md), [проверки оформления](docs/tf2-verification.md).

Одностраничный сайт на русском: первый экран, информация о себе, навыки, проекты с фильтрами, опыт, участие в форумах и контакты. Статьи, фотогалерея и резюме временно отключены до появления материалов; их исходники сохранены. HTML5, CSS3 и обычный JavaScript ES6+. Содержимое загружается из JSON. Фреймворки, сборка, база данных, серверная часть и `.venv` не нужны.

**Начальное наполнение демонстрационное.** Имя, биография, навыки, проекты и опыт нужно заменить своими данными. Ни один пример не является утверждением о владельце сайта. Контакты пустые, PDF не добавлен.

## Временно отключённые разделы и восстановление

Статьи, фотографии и резюме отключены комментариями `TEMP` в `index.html` и `scripts/app.js`. Они отсутствуют в общей навигации (включая мобильное меню), на странице и в загрузке данных; у резюме отключена также кнопка первого экрана. JSON, медиа, общие функции `scripts/content.js`, анимация `scripts/motion.js` и стили `styles/main.css` сохранены.

Каждый раздел можно вернуть отдельно после добавления материалов. Снимите только указанные оболочки HTML-комментариев `<!-- … -->`, JS-комментариев `/* … */` и префиксы `//` перед соответствующими строками кода; пояснения оставьте отдельными комментариями:

| Раздел | Блоки `TEMP` в `index.html` | Блоки `TEMP` в `scripts/app.js` | Данные и файлы |
| --- | --- | --- | --- |
| Статьи | `articles:nav`, `articles:section` | `articles:import`, `pdf:import`, `articles:render`, `articles:load` | `content/articles.json`, `content/profile.json → sections.articles`, `assets/articles/` |
| Фотографии | `photos:nav`, `photos:section`, `photos:dialog` | `photos:viewer` (включая состояние и все обработчики), `photos:load` | `content/photos.json`, `content/profile.json → sections.photos`, `assets/images/photos/` |
| Резюме | `resume:nav`, `resume:hero`, `resume:section` | `pdf:import`, `resume:bind`, `resume:render` | `content/profile.json → resume, sections.resume, hero.secondaryAction`, настоящий PDF в `assets/resume/` |

`pdf:import` общий для статей и резюме: достаточно раскомментировать его один раз. HTML и связанные JS-блоки выбранного раздела возвращайте вместе, чтобы обработчики не обращались к отсутствующему DOM. Заполнение JSON само по себе разделы не включает. Подробности полей приведены ниже.

Контакты сейчас имеют видимый номер `06`. При восстановлении разделов пересчитайте номера видимых разделов в `content/profile.json → sections.*.number`, в блоке `TEMP sections:number` верните исходный `span` с `data-bind` вместо временного `<span>06</span>` и согласуйте резервные номера в HTML. При возврате всех трёх разделов исходные номера уже подходят: статьи `06`, фотографии `07`, резюме `08`, контакты `09`.

В `tests/content.test.mjs` обновите ожидания теста «Разделы без материалов отсутствуют…» для возвращённых разделов и порядок активных разделов. Проверки JSON, сохранённых файлов, PDF, DOI и доступности продолжают выполняться и сейчас. Запустите `node --test` и повторите проверку интерфейса на 375, 768 и 1440 px. После проверки опубликуйте изменённые файлы обычным способом через GitHub Pages.

## Быстрый запуск

Зависимостей для установки нет. В Windows запустите из PowerShell:

```powershell
cd 'F:\Projects\Business card website'
.\start.cmd
```

Откройте [http://127.0.0.1:4173/](http://127.0.0.1:4173/). Оставьте окно сервера открытым; остановка — `Ctrl+C`.

`start.cmd` автоматически выбирает доступный Node.js или уже установленный Python 3 (через `py` либо `python`). Он ничего не устанавливает и не меняет PATH. Python используется только как готовый HTTP-сервер для просмотра, `.venv` не требуется. Если оба интерпретатора отсутствуют, понадобится установить один из них или воспользоваться другим статическим HTTP-сервером.

Если PowerShell сообщает «node не распознано», а Python уже установлен, можно запустить напрямую:

```powershell
py -3 -m http.server 4173 --bind 127.0.0.1
```

При наличии Node.js 20 или новее в PATH доступен прежний запуск:

```powershell
node scripts/serve.mjs
```

Если порт занят, используйте другой, например:

```powershell
node scripts/serve.mjs --port 8080
# Или для Python:
py -3 -m http.server 8080 --bind 127.0.0.1
```

`serve.mjs` — только инструмент локального просмотра. На GitHub Pages он не запускается. Устанавливать npm-пакеты не требуется. При наличии npm можно также использовать `npm start` и `npm test`.

**Не открывайте `index.html` двойным щелчком:** браузер ограничивает ES-модули и загрузку JSON по протоколу `file://`. Любой статический HTTP-сервер также подойдёт. Если Python уже установлен, альтернатива: `python -m http.server 4173 --bind 127.0.0.1`. Python не является зависимостью сайта, виртуальное окружение не требуется.

## Изменение содержимого

Правьте файлы в `content/` в любом текстовом редакторе. Сохраняйте UTF-8 и валидный JSON: двойные кавычки, без комментариев и без запятой после последнего поля. После сохранения обновите страницу. Можно добавить поля в объект: неизвестные поля игнорируются.

### Имя и тексты

В `content/profile.json`:

- `name` — имя; `brand` — короткая подпись в шапке.
- `area` — область деятельности; `pageTitle`, `description` — название вкладки и SEO-описание.
- `hero` — заголовок первого экрана, описание и подписи кнопок.
- `overview` — три кратких пункта под первым экраном; их количество можно менять.
- `about` — заголовок, вводная фраза, массив абзацев, примечание и принцип работы.
- `sections` — названия, номера, заголовки и вводные тексты разделов. Здесь же подписи навигации.
- `footer` — подпись внизу страницы.

Для портрета добавьте файл в `assets/images/photos/`, заполните `about.portrait` относительным путём и `about.portraitAlt` содержательным описанием. В `about.portraitCaption` укажите подпись. Пустой путь оставляет графическую заглушку.

### Навыки

В `content/skills.json` каждая запись — группа: `title`, `description`, `icon`, `isExample`, `items` (массив навыков). Порядок записей и элементов совпадает с порядком отображения. Иконки: `orbit`, `code`, `layers`, `grid`, `file`, `mail`, `github`, `message`, `person`, `arrow`. Уровни владения и процентные оценки не выдумываются.

### Проекты

1. Положите обложку в `assets/images/projects/`. Рекомендуются WebP/AVIF/JPEG, ширина 1200 px, размер до 200–300 КБ. SVG тоже поддерживается.
2. Добавьте объект в `content/projects.json`. Например:

```json
{
  "id": "my-project",
  "title": "Название реального проекта",
  "category": "Языковые модели",
  "isExample": false,
  "featured": false,
  "description": "Какую задачу нужно было решить.",
  "contribution": "Что именно вы сделали.",
  "technologies": ["Укажите свои технологии"],
  "result": null,
  "cover": "assets/images/projects/my-project.webp",
  "coverAlt": "Содержательное описание обложки",
  "repository": null,
  "demo": null
}
```

`featured: true` делает карточку широкой на большом экране. Порядок задаётся массивом: для перестановки переместите объект целиком. Для удаления удалите объект, при желании удалите ненужную обложку. Категории фильтров формируются автоматически. Если категорий меньше двух, фильтры скрываются. Новые проекты не требуют изменения HTML или JavaScript.

`result`, `repository` и `demo` необязательны: используйте `null` или пустую строку. Пустые блоки и кнопки не создаются. Ссылки должны начинаться с `https://`. Если обложка недоступна, появляется графическая заглушка.

### Опыт

`content/experience.json`: `period` (текст дат), `title` (роль или этап), `organization` (может быть `null`), `type`, `description`, `highlights` (массив пунктов), `isExample`. Добавляйте только реальные сведения. Самостоятельная практика допустима; указывать работодателя необязательно. Новые записи появляются в порядке массива.

### Участие в форумах

В `content/forums.json` каждая запись имеет поля:

- `title` — название форума, конференции или другого мероприятия;
- `period` — дата либо период в свободной текстовой форме;
- `location` — место или онлайн-формат;
- `role` — ваша подтверждённая роль;
- `description` — короткий рассказ об участии;
- `link` — необязательный HTTPS-адрес мероприятия, выступления или материалов;
- `isExample` — `true` для примера, `false` после замены реальными сведениями.

Добавляйте объекты в массив, удаляйте и переставляйте их: порядок файла определяет порядок карточек. Пустые необязательные поля и неподдерживаемые ссылки не создают пустых блоков. Пустой массив `[]` показывает состояние «Мероприятия скоро появятся».

### Научные статьи и их PDF

В `content/articles.json` используются поля:

```json
{
  "title": "Название вашей подтверждённой работы",
  "authors": ["Автор в порядке публикации"],
  "year": 2026,
  "venue": "Название научной площадки",
  "status": null,
  "description": "Краткая аннотация работы",
  "doi": null,
  "link": null,
  "pdf": null,
  "isExample": false
}
```

`authors` — массив имён в нужном порядке; `year` — число или текст; `venue` — журнал, конференция или другая площадка. `status` необязателен: например, «Препринт» или «Опубликовано». Не обозначайте работу опубликованной до подтверждения её статуса.

В `doi` можно указать настоящий DOI в форме `10.…/…` либо официальный HTTPS-адрес `https://doi.org/…`. `link` — отдельная HTTPS-ссылка на площадку. Не заполняйте их вымышленными идентификаторами. Для локального PDF положите файл в `assets/articles/` и задайте, например, `"pdf": "assets/articles/my-paper.pdf"`. Сайт проверяет доступность и сигнатуру `%PDF-` так же, как у резюме. Ссылка на скачивание появляется только для доступного PDF; отсутствие DOI, статуса, ссылки или PDF не оставляет пустую строку действий.

Добавление, удаление и перестановка статей выполняются объектами массива без изменения HTML. Пустой массив `[]` показывает «Статьи скоро появятся». Заголовки, вводные тексты, номера обоих разделов и короткие подписи меню `navLabel` находятся в `profile.json → sections.forums/articles`.

### Фотографии

Добавьте изображение в `assets/images/photos/`, затем запись в `content/photos.json`:

```json
{
  "src": "assets/images/photos/my-photo.webp",
  "alt": "Что изображено на фотографии",
  "caption": "Подпись к фотографии",
  "isPlaceholder": false
}
```

Переставляйте и удаляйте объекты для управления галереей. Для каждой фотографии требуется осмысленный `alt`. Изображения загружаются отложенно, область под них зарезервирована. Нажатие открывает увеличенный просмотр: `←`/`→` переключают снимки, `Escape` закрывает. После закрытия фокус возвращается к исходной фотографии.

### PDF резюме

1. Добавьте настоящий PDF как `assets/resume/resume.pdf`.
2. В `content/profile.json` задайте `resume.path`: `"assets/resume/resume.pdf"`.
3. При необходимости измените `resume.filename`, `label`, `readyText`, `buttonLabel`.

Если путь пустой, файл отсутствует, сеть недоступна или документ не начинается с сигнатуры `%PDF-`, сайт показывает состояние заглушки и не создаёт ссылку скачивания. После добавления файла и обновления страницы появится рабочая кнопка. Первый запрос проверяет начало файла; если хостинг не поддерживает Range, поток прекращается после чтения сигнатуры. Текст заглушки регулируют `emptyTitle` и `emptyText`.

### Контакты

В `content/contacts.json` заполните `items`. Для почты `url` должен иметь вид `mailto:ваш-адрес`, для остальных площадок — полный HTTPS-адрес. В `value` укажите видимую подпись, в `label` — название площадки. Пустые и неподдерживаемые ссылки не показываются. Когда нет ни одной ссылки, используются `emptyTitle` и `emptyText`. Для новой площадки достаточно ещё одного объекта. Формы отправки сообщений нет.

### Как убрать пометки примеров

Сначала замените весь демонстрационный контент реальными данными:

1. В `profile.json` замените имя, тексты, подписи портрета, вводные тексты `sections`, примечание `about.note` (можно сделать пустым), затем установите `isExample: false`.
2. В каждой подтверждённой записи навыков, проектов, опыта, форумов и научных статей установите `isExample: false`. Удалите оставшиеся примеры.
3. Замените фото и установите `isPlaceholder: false`.
4. Добавьте реальные контакты и PDF, когда они готовы.
5. Задайте `pageTitle` и `description` в `profile.json`: название вкладки и описание обновляются из JSON. Начальные метаданные в HTML нейтральные, поэтому править вёрстку для персонализации не требуется. Сервисы превью ссылок, не выполняющие JavaScript, могут показывать нейтральное название «Портфолио — Искусственный интеллект».

Флаги независимы: выключение общей пометки не скрывает пометки у оставшихся примеров. Сами пометки служебные, не заменяют проверку правдивости содержимого. Тесты поддерживают как примеры, так и заполненное портфолио; после персонализации менять их не требуется.

## Оформление и доступность

Семантические цвета находятся в `:root` файла `styles/main.css`: графитовый фон `#2B2724`, коричневые поверхности `#39332E`, кирпично-красный акцент `#9E3D2C`, ржавые детали `#C77B46`, светлый текст `#F0E4CC` и бумага `#EADFC7`. Для бумаги предусмотрены отдельные тёмные цвета текста, для кнопок — светлый текст. Дополнительные стили, материал и параметры слоёв — в `styles/theme-tf2.css`. [Как заменить фон и инженера](docs/tf2-assets.md).

Навигация закреплена; `scroll-padding-top` оставляет место над заголовками при переходе по якорям. На экранах уже 1200 px девять ссылок собраны в раскрывающееся меню с собственной прокруткой на низких окнах. Используются семантические разделы, ссылка пропуска навигации, заметный фокус, настоящие кнопки и нативный `dialog`. JavaScript нужен для загрузки JSON; при его отключении показано объяснение.

### Настройка движения

Параметры в `:root` файла `styles/main.css`:

| Переменная | По умолчанию | Назначение |
| --- | --- | --- |
| `--reveal-duration` | `850ms` | Длительность появления |
| `--reveal-distance` | `16px` | Небольшое вертикальное смещение |
| `--reveal-stagger` | `80ms` | Шаг задержки соседних карточек |
| `--reveal-delay-max` | `240ms` | Максимальная задержка |
| `--reveal-easing` | `cubic-bezier(.2, .65, .3, 1)` | Кривая появления |

В TF2-теме фон и инженер статичны; движение ограничено повторяемыми появлениями карточек. Кнопки и меню сохраняют переходы порядка 200–250 мс. Появления повторяются при прокрутке в обе стороны: внутренняя зона с отступом 24 px запускает эффект один раз, а полный выход за экран с буфером 32 px разрешает следующий запуск. Буфер больше смещения и защищает от мигания около края; высоким карточкам не требуется показывать фиксированный процент своей высоты.

`MutationObserver` подключает карточки после загрузки JSON, повторной попытки загрузки и фильтрации, освобождая удалённые элементы. Положение фокуса не изменяется; `:focus-within` немедленно отключает появление родительской карточки. При `prefers-reduced-motion: reduce` вся анимация и декоративное движение отключаются, включая изменение настройки во время работы. При отсутствии `IntersectionObserver` контент остаётся видимым, загрузка и навигация работают. Механизм не меняет размеры блоков и не перехватывает прокрутку.

При недоступном или невалидном JSON ошибка ограничивается соответствующим разделом; кнопка «Повторить загрузку» повторяет запрос. Личные данные вставляются как текст, а не исполняемый HTML. Внешние ссылки открываются с `noopener noreferrer`.

## Проверка и сборка

Сборка отсутствует: в публикацию идут исходные статические файлы.

```powershell
node --test
node --check scripts/app.js
node --check scripts/content.js
node --check scripts/motion.js
node --check scripts/serve.mjs
```

Автотесты проверяют JSON, маркировку примеров, метаданные форумов/статей, DOI, контраст основных цветов, изображения, alt, якоря, относительные пути, фильтры, необязательные поля, ошибки загрузки, сигнатуру PDF и HTTP-публикацию как в корне, так и в `/repository/`. Проверки движения охватывают повторный вход, колебания у границы, новые и удалённые карточки, фокус, reduced motion и отсутствие наблюдателя. Используется `node:test` без установки зависимостей.

Ручная проверка в браузере: ширины 375, 768 и 1440 px; отсутствие горизонтальной прокрутки; все активные якоря; мобильное меню и `Escape`; фокус с `Tab`; фильтры проектов; отсутствие ссылок, заглушек и загрузки временно отключённых разделов; пустые состояния оставшихся разделов и отсутствие вымышленных контактных ссылок. После восстановления галереи проверяйте её открытие, стрелки, `Escape` и возврат фокуса; после восстановления резюме — доступность PDF и состояние отсутствующего файла. Для проверки адреса с подпапкой:

```powershell
node scripts/serve.mjs --port 4174 --base /repository/
```

Откройте [http://127.0.0.1:4174/repository/](http://127.0.0.1:4174/repository/). Не используйте начальный `/` в путях контента: правильно `assets/images/photo.webp`, а не `/assets/images/photo.webp`. CSS, ES-модули и JSON сами определяют путь сайта; переписывать адрес репозитория в исходниках не требуется.

## Публикация на GitHub Pages из ветки

Доступ к GitHub для локальной работы не нужен. Если репозитория ещё нет:

1. Создайте репозиторий в своём GitHub. Для пользовательского сайта имя — `username.github.io`; для сайта проекта подходит любое имя репозитория.
2. Загрузите содержимое этой папки в корень выбранной ветки, например `main`. В корне обязательно должны быть `index.html`, `content/`, `styles/`, `scripts/`, `assets/` и `.nojekyll`.
3. В репозитории откройте **Settings → Pages → Build and deployment**.
4. В **Source** выберите **Deploy from a branch**.
5. Выберите ветку **main** (или свою ветку) и папку **/ (root)**, сохраните.
6. Дождитесь завершения встроенной публикации GitHub Pages. Адрес появится на этой же странице.

Адрес пользовательского сайта: `https://username.github.io/`. Сайта проекта: `https://username.github.io/repository/`. Оба варианта поддерживаются. Публикация из ветки не требует собственного workflow, сборки, токенов в коде или сервера.

Если Git уже установлен, начальная загрузка из PowerShell:

```powershell
git init -b main
git add .
git commit -m "Create personal AI portfolio"
git remote add origin https://github.com/USERNAME/REPOSITORY.git
git push -u origin main
```

Замените `USERNAME` и `REPOSITORY` своими значениями. GitHub может запросить вход вашим привычным способом. В проекте не нужно сохранять пароли или токены. Папка `.qa/` предназначена для локальных проверок и исключена из Git.

### Обновление сайта

Измените JSON и/или добавьте медиа, проверьте локальный сайт, затем сохраните изменения в выбранную ветку:

```powershell
git add .
git commit -m "Update portfolio content"
git push
```

GitHub Pages опубликует новую версию автоматически. Если изменения не видны, дождитесь окончания публикации в **Actions** и обновите страницу с `Ctrl+F5`.

Если после изменения HTML исчезло всё содержимое из JSON, проверьте ошибки JavaScript и обновите страницу с `Ctrl+F5`: браузер мог сохранить старый модуль, обращающийся к уже отключённым элементам. При изменении связанного HTML/JS обновляйте параметр `v` у `scripts/app.js` в `index.html`, чтобы новая разметка загружала актуальный скрипт. Это также важно для локального просмотра через стандартный HTTP-сервер Python, который не задаёт `Cache-Control: no-cache`.

### Перед личной публикацией

Замените демонстрационные тексты, проверьте реальные ссылки и убедитесь, что PDF и фотографии можно публиковать. Если данных пока нет, оставьте соответствующие состояния заглушек. В текущей поставке GitHub-репозиторий не настроен и публичная публикация не выполнялась.
